# AI Agent Operational Guidelines (GEMINI.md)

## 1. 핵심 실행 원칙 (Core Principles)
*최대 10개 내외의 '근육 기억'으로 유지하십시오.*

1. **생성과 검증 분리**: 코드 작성 후 반드시 별도의 검증 패스를 수행한다. (동시 수행 금지)
2. **제약 선행 로딩**: 생성 전 프로젝트 스택, 컨벤션, 제약 사항 파일을 먼저 읽는다.
3. **테스트 우선 (TDD)**: 실패하는 테스트 작성 -> 통과 코드 구현 -> 검증 단계를 준수한다.
4. **3트랙 검증**: 모든 코드는 (1) 로직 버그 (2) 예외 케이스 (3) 보안 관점에서 점검한다.
5. **도구 최적화**: 포맷팅, 린트, 파일 조작은 CLI/스크립트를 사용하고, LLM 토큰은 판단과 생성에 집중한다.
6. **선검증 후호출**: MCP나 외부 API 호출 전, 환경 변수와 인증 유효성을 먼저 확인한다.
7. **반복의 자동화**: 3회 이상 반복되는 패턴은 스킬 (`00_CORE/toolkit/` 또는 `~/.gemini/skills/`)로 승화시킨다.

## 2. 지식 Vault 활용 및 트리거
*복잡한 문제 해결을 위해 외부 지식 창고(`~/ai-brain/`)를 참조하십시오.*

### 폴더 구조 정의
Gemini는 필요한 정보를 찾기 위해 아래 구조를 스스로 탐색할 수 있습니다: 

- **00_CORE**: 항상 참조할 핵심 원칙, 페르소나, 행동 스킬 
- **01_INTAKE**: 새로 수집된 미분류 지식 처리 파이프라인 
- **02_MEMORY**: 자주 사용되는 구조화된 지식 (패턴/결정 레코드/스킬) 
- **03_REFERENCE**: 깊이 있는 기술 문서 및 참고 자료 (필요시 검색) 
- **04_ACTIVE**: 현재 진행 중인 활성 프로젝트 관련 컨텍스트 
- **90_ARCHIVE**: 더 이상 유효하지 않거나 오래된 과거 자료

### 지식 조회 트리거
다음 상황에서만 `~/ai-brain/`을 검색하십시오:

- **프로젝트 시작**: 새로운 라이브러리, 도구, MCP 서버 도입을 검토할 때 -> `04_ACTIVE/` 내 관련 프로젝트 컨텍스트 확인. 
- **의사결정 필요**: 아키텍처 패턴 선택(A vs B)이 필요할 때 -> `02_MEMORY/decisions/` 또는 `patterns/` 확인. 
- **오류 해결**: 동일한 접근 방식이 2회 연속 실패하여 대안이 필요할 때 -> `00_CORE/toolkit/`에 사용 가능한 진단 도구가 있는지 확인.  
- **기준 모호**: `00_CORE` 또는 `02_MEMORY`에 정의된 프로젝트 표준이 모호할 때 -> `00_CORE/guardrails.md` 확인.

## 3. 인사이트 적용 전 8항 검증 (Pre-apply Validation)
*새로운 지식을 코드베이스에 반영하기 전, 아래 필터를 통과해야 합니다.*

- **BLOCK**: 기존 가이드라인(`00_CORE`)이나 프로젝트 컨벤션과 충돌하는가? -> **적용 금지**
- **SKIP**: 이미 더 나은 대안(`02_MEMORY`)이 있는가? 또는 작업 범위에 비해 변경이 너무 큰가? -> **건너뛰기**
- **DEPRIORITIZE**: 효과를 즉시 검증할 수 없는가? -> **우선순위 낮춤**
- **REPORT**: 버전 적합성이 불확실하거나 특정 조건에서만 유효한가? -> **사용자 확인 요청**
- **REPORT**: 다른 인사이트와 충돌(Trade-off) 가능성이 있는가? -> **절충안 보고**
